# Хранилище Plesk и рост каталогов

## Что занимает место

Страницы каталогов ZakonExpert формируются динамически из общих наборов
данных. Десять тысяч URL не означают десять тысяч HTML-файлов и сами по
себе почти не увеличивают диск.

Проверить приложение из его корневой папки:

```bash
npm run storage:audit
du -h --max-depth=2 . 2>/dev/null | sort -h | tail -30
find . -type f -size +20M -printf '%s %p\n' 2>/dev/null | sort -nr | head -30
```

Если Plesk показывает заметно больше, чем `Project (without .git)`, значит
место занято вне приложения. Проверить весь домашний каталог подписки:

```bash
du -h --max-depth=2 "$HOME" 2>/dev/null | sort -h | tail -40
find "$HOME" -xdev -type f -size +20M -printf '%s %p\n' 2>/dev/null | sort -nr | head -40
```

Особенно проверить:

- `app.log`, `exceptions.log`, `rejections.log` и системные логи Plesk;
- старые резервные копии и предыдущие версии деплоя;
- `node_modules` с dev-зависимостями;
- копии загруженных изображений и архивов.

## Логи

По умолчанию приложение пишет только в stdout/stderr, которые собирает Plesk.
Файловые логи можно включить переменной `FILE_LOGS_ENABLED=true`, но каждый
из них ограничен ротацией: не более двух файлов по 2 МБ.

Существующие большие логи надо сначала скачать, если они нужны для истории,
а затем очистить через файловый менеджер Plesk. Файлы из `data/` удалять
нельзя: там находятся рабочие базы, комментарии и заявки.

## Уплотнение рабочих баз

NeDB хранит изменения в дописываемом журнале. Приложение теперь автоматически
уплотняет все рабочие базы раз в шесть часов. После массового импорта реестра
уплотнение также выполняется сразу.

Для однократного освобождения накопившегося места:

1. Остановить Node.js-приложение в Plesk.
2. В корневой папке сайта выполнить:

   ```bash
   npm run storage:compact -- --confirm-offline
   ```

3. Запустить приложение снова и повторить `npm run storage:audit`.

Команда не удаляет актуальные записи. Она переписывает каждый известный файл
NeDB без старых версий изменённых и удалённых документов. Запускать её
одновременно с работающим приложением нельзя.

## Установка зависимостей

На production-сервере использовать:

```bash
npm ci --omit=dev --ignore-scripts
```

Для текущего проекта production-зависимости занимают примерно 31 МБ вместо
67 МБ с инструментами разработки.

## Как хранить новые официальные реестры

Реестры нотариусов, ЧСИ и адвокатов уже переведены с трёх CSV на снимки:

- `registry/notaries.json.gz`;
- `registry/bailiffs.json.gz`;
- `registry/lawyers.json.gz`.

В сумме исходники занимают около 0,5 МБ вместо 2,1 МБ. При обновлении
нотариусов новый снимок записывается атомарно: неполная загрузка не заменит
рабочий файл. Импортеры проверяют формат, тип реестра и минимальную полноту до
замены рабочей базы.

Для больших новых наборов используется одна схема:

1. Получить данные через официальный API или выгрузку.
2. Оставить только поля, которые выводятся на сайте.
3. Нормализовать и удалить дубли до публикации.
4. Сохранить один минифицированный снимок `JSON.gz` на реестр.
5. Строить каталог и карточки динамически из этого снимка.
6. Не хранить на сервере одновременно исходный Excel/CSV, полный JSON и
   сжатый JSON. Рабочая NeDB-база остаётся отдельным индексом для быстрых
   запросов и автоматически уплотняется.

Обычный JSON не всегда меньше CSV. Экономию даёт удаление лишних полей и
gzip: снимок нотариусов уменьшился примерно с 1,6 МБ до 0,4 МБ.
