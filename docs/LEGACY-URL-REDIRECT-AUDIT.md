# Аудит старых URL и редиректов

## Проблема

Каждая из этих страниц физически существует как один файл в `public/`, но до этого исправления была доступна одновременно под **двумя URL** — старым (по имени файла) и новым «чистым» (зарегистрирован отдельным маршрутом в `server.js`). Оба URL отдавали 200 с идентичным содержимым, но `<link rel="canonical">` внутри HTML указывал только на новый URL — старый URL оставался живым дублем без редиректа.

| Старый URL | Новый (канонический) URL | Статус ДО | Исправление | Статус ПОСЛЕ | Нужен переобход |
|---|---|---|---|---|---|
| `/ispolnitelnaya-nadpis` (+`.html`) | `/otmena-ispolnitelnoi-nadpisi` | 200 (дубль) | 301 | 301 → 200 на канонике | Да |
| `/spornost-dolga` (+`.html`) | `/vozrazhenie-na-ispolnitelnuyu-nadpis` | 200 (дубль) | 301 | 301 → 200 на канонике | Да |
| `/chsi-arest-schetov` (+`.html`) | `/snyatie-ogranichenii-chsi` | 200 (дубль) | 301 | 301 → 200 на канонике | Да |
| `/zapret-registracionnyh-deystviy` (+`.html`) | `/snyatie-zapreta-registracionnyh-deistvii` | 200 (дубль) | 301 | 301 → 200 на канонике | Да |
| `/grafik-platezhey` (+`.html`) | `/grafik-oplaty-zadolzhennosti` | 200 (дубль) | 301 | 301 → 200 на канонике | Да |

Реализация: `LEGACY_ALIAS_REDIRECTS` в `server.js` (зарегистрирован до `express.static`, чтобы редирект срабатывал раньше отдачи статического файла). Один хоп, без цепочек редиректов (проверено `curl -D-`).

Также удалены:
- 4 неактивных (недостижимых) дублирующих маршрута из `servicePages` — эти ключи больше никогда не срабатывали бы, так как редирект их перехватывает раньше.
- 4 записи старых URL из `sitemap-pages.xml` (`/ispolnitelnaya-nadpis`, `/spornost-dolga`, `/zapret-registracionnyh-deystviy`, `/grafik-platezhey`) — канонические версии уже присутствовали в сайтмапе отдельными записями.

Внутренние ссылки на старые URL по всему сайту уже были заменены на канонические в рамках более раннего исправления каннибализации (см. `docs/SEARCH-INTENT-MAPPING.md`, раздел «Главная находка сессии») — редирект здесь закрывает оставшийся пробел: прямые заходы, старые внешние ссылки и уже проиндексированные Google/Yandex URL.

## Общий `.html`-суффикс на всех остальных страницах — тоже исправлено (обновление)

Изначальное предположение (что Google/Яндекс сами разберутся через self-referencing canonical без редиректа) **не подтвердилось на реальных данных**. Свежая выгрузка Яндекс.Вебмастера (`https___zakonexpert.kz_-Performance-on-Search-2026-07-15.xlsx`, лист «Страницы») показала, что Яндекс независимо проиндексировал `.html`-версии как отдельные URL и показывает их в поиске на **худших позициях**, чем должна быть каноническая версия:

| URL (проиндексирован Яндексом) | Показы | Клики | Позиция |
|---|---|---|---|
| `/snyatie-aresta-so-scheta.html` | 521 | 1 | **16.0** (2-я страница выдачи) |
| `/zakony.html` | 379 | 3 | 9.0 |
| `/otmena-resheniya-suda.html` | 348 | 4 | 8.1 |
| `/besspornost-dolga.html` | 33 | 4 | 5.9 |

Это прямое доказательство того, что дублирование URL по `.html`-суффиксу **реально мешает ранжированию**, а не является безобидным техническим нюансом. Добавлен общий редирект (`HTML_SUFFIX_REDIRECT_EXCLUDE` + `app.get(/^\/.+\.html$/, ...)` в `server.js`, зарегистрирован перед `express.static`): любой запрос вида `/name.html` для реально существующего файла в `public/` теперь получает 301 на `/name` (для главной — специальный случай: `/index.html` → `/`, а не `/index`, согласно self-referencing canonical на `/`).

Исключения (остаются на `.html`, не редиректятся): 2 файла верификации поисковых систем — `/googlerGbK9GM3kA42xzTzGMQs4VZju46dDdZjQdmOigQjnKY.html`, `/yandex_decc99fa3bf371ce.html` — им обязательно нужен точный URL для подтверждения владения сайтом.

Внутренние ссылки на `.html`-суффикс проверены отдельно — на сайте их **нет ни одной** (все внутренние `href` уже используют чистые URL), поэтому редирект влияет только на внешние заходы (проиндексированные Яндексом/Google URL, старые внешние ссылки, ручной ввод) — обычная навигация по сайту не создаёт лишний хоп редиректа.
