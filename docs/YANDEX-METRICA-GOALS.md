# Яндекс.Метрика — цели (JavaScript-события)

Счётчик: **110748931**. Установлен на всех пользовательских страницах (см. `docs/STAGE4-DEPLOY-CHECKLIST.md` для проверки после публикации).

Все цели — тип **JavaScript-событие**, отправляются через `ym(110748931, 'reachGoal', <идентификатор>, <params>)`. Мост реализован в `public/js/analytics-events.js` (`sendYandexGoal()` / `window.ZE_sendYandexGoal`) и вызывается из `public/js/chatbot.js` (для `click_phone`/`click_whatsapp`) и автоматически из `window.ZE_trackEvent()` для остальных целей.

Все параметры — не персональные (см. допустимый список ниже). ИИН, ФИО, телефон клиента, текст сообщения, содержимое документа **никогда** не передаются.

## Основные конверсии (лид)

| Идентификатор | Где вызывается | Как проверить | Приоритет |
|---|---|---|---|
| `click_whatsapp` | Клик по `wa.me`-ссылке с одним из наших номеров (main/advocate/mediator) — `public/js/chatbot.js` | Кликнуть по WhatsApp-кнопке на любой странице, посмотреть в Метрике «Вебвизор» → событие reachGoal | Высокий |
| `click_phone` | Клик по `tel:`-ссылке с одним из наших номеров — `public/js/chatbot.js` | Кликнуть по номеру телефона | Высокий |
| `submit_iin` | Отправка формы проверки ИИН — главная, `/#checker-section` | Пройти проверку по ИИН на главной | Высокий |
| `send_document` | Подтверждение отправки документа на проверку (зарезервировано под будущую форму загрузки) | — (пока не вызывается в коде) | Высокий |
| `click_cta_bailiff` | Клик по CTA на карточке ЧСИ («Проверить по ИИН» или «Написать в WhatsApp») — `views/bailiff/page.ejs` | Открыть любую `/bailiff/:slug`, кликнуть по CTA | Высокий |
| `click_cta_notary` | Клик по CTA на карточке нотариуса — `views/notary/page.ejs` | Открыть любую `/notary/:slug`, кликнуть по CTA | Высокий |
| `click_whatsapp_after_download` | Клик по любой `wa.me`-ссылке в той же сессии, где ранее было `download_document` — `public/js/analytics-events.js` | Скачать документ на `/dokumenty`, затем кликнуть WhatsApp | Высокий |

## Второстепенные цели

| Идентификатор | Где вызывается | Как проверить | Приоритет |
|---|---|---|---|
| `download_document` | Клик по `a[download]` или ссылке в `/downloads/` — автоматически, любая страница | Скачать любой образец документа на `/dokumenty` | Средний |
| `calculator_completed` | Завершение калькулятора — `/calculator` | Пройти калькулятор до конца | Средний |
| `bin_search_completed` | Завершение поиска по БИН — `/bin-search` | Выполнить поиск | Средний |
| `click_document_review` | Клик по кнопке «Проверить документ в WhatsApp» на `/dokumenty` | Открыть `/dokumenty`, кликнуть нижний CTA | Средний |

## Допустимые параметры целей

`page_path`, `page_type`, `cta_position`, `source_entity_type`, `source_page`, `service_type`, `document_type`, `utm_source`, `utm_medium`, `utm_campaign`. Всё остальное отбрасывается на клиенте перед отправкой в `ym()` (см. `YM_ALLOWED_PARAMS` в `analytics-events.js`).

## Как создать цели в интерфейсе Метрики (ручное действие владельца)

1. Яндекс Метрика → счётчик 110748931 → **Настройки** → **Цели** → **Добавить цель**.
2. Тип цели — **JavaScript-событие**.
3. В поле «Идентификатор события» указать точное значение из колонки «Идентификатор» выше (например `click_whatsapp`).
4. Повторить для каждой из 11 целей выше.
5. В группе «Основные цели» (если используется отчёт «Конверсии») отметить 7 целей из раздела «Основные конверсии».

## Защита персональных данных / Webvisor

- Поля ввода (ИИН, телефон, документ) не имеют кастомной логики, раскрывающей их значения в параметры аналитики или в консоль — используется стандартная защита Вебвизора (маскирование полей форм по умолчанию).
- Ни один из вызовов `sendYandexGoal()`/`ZE_trackEvent()` в кодовой базе не передаёт значения полей форм — целиком проверено (см. `docs/LOCAL-ANALYTICS-SECURITY.md`).
