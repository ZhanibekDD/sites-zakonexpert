# Реестр компаний Казахстана

Источник: официальный набор `gbd_ul` Министерства юстиции РК на
`data.egov.kz`. На 16.07.2026 набор содержит 984 615 записей.

База сайта хранится в одном компактном файле `data/companies.sqlite`. Исходные
записи не создают отдельные HTML-файлы: карточки `/company/:slug` формируются
динамически. Slug вычисляется при запросе и не дублирует название в базе.

## Первый полный импорт

1. Указать `EGOV_API_KEY` в `.env`.
2. Остановить Node.js в Plesk.
3. Выполнить:

```bash
npm run import-companies -- --all --confirm-offline
```

Импорт сохраняет прогресс прямо в рабочей SQLite-базе. После обрыва достаточно
повторить команду: загрузка продолжится с последней сохранённой страницы. Старая
и новая полные копии одновременно не создаются — это экономит место на хостинге.

Для проверки одной страницы без активации базы:

```bash
npm run import-companies -- --pages=1
```

После полного импорта запустить Node.js заново. В sitemap index автоматически
появятся файлы по 50 000 карточек компаний.

## Распределение по регионам

Каждая компания получает `region_slug` (область или город из адреса), вычисляемый
модулем `modules/company-region.js` по тексту `address_ru`. Новые импорты заполняют
это поле автоматически. Каталог по регионам доступен на `/companies/regions` и
`/companies/region/:slug`.

База, импортированная **до** появления этого поля, требует однократного
пересчёта:

1. Остановить Node.js в Plesk.
2. Выполнить:

```bash
npm run backfill-company-regions
```

Скрипт проходит по всем записям без `region_slug` пачками по 5000 и сохраняет
прогресс прямо в рабочей базе — при обрыве достаточно запустить команду снова.
После завершения запустить Node.js заново.

## Контакты из бизнес-справочника

Официальный набор `gbd_ul` не публикует телефон, email, сайт или соцсети —
только БИН, адрес, руководителя и статус. `scripts/import-directory-contacts.js`
дополняет это открытым бизнес-справочником.

Источник — архив вида «Казахстан.zip» (~1500 xlsx-файлов по категориям, без
БИН, но с контактами, ~615 000 строк). Сырой архив **не хранится в проекте и
не загружается на сервер** — 88 МБ на диске с и так ограниченной квотой того
не стоит. Вместо этого в `registry/companies-directory-contacts.json.gz`
лежит один сжатый снимок (~36 МБ) со всеми нужными полями — его и читает
`import-directory-contacts.js` через встроенный в Node `zlib`, без сторонних
библиотек. Если появится новый архив, снимок пересобирается локально:

```bash
npm run build-directory-snapshot -- --archive="Казахстан.zip"
```

(нужен `adm-zip` — он в `devDependencies`, на сервере не нужен и не ставится
через `npm ci --omit=dev`) и получившийся `.json.gz` закоммитить.

Логика:

- Совпадение находится по нормализованному названию (без «ТОО»/«Товарищество
  с ограниченной ответственностью» и т.п.) и, если у обеих сторон известен
  регион, регион тоже должен совпасть — иначе запись не считается совпадением.
- У найденной компании дозаполняются **только пустые** поля контактов —
  существующие данные никогда не перезаписываются.
- Если совпадения нет — запись добавляется как новая, без БИН. Такие записи
  автоматически не участвуют в публичном sitemap (`is_indexable` требует
  подтверждённый 12-значный БИН — см. `modules/company-quality.js`), но
  доступны через поиск и каталог на самом сайте.
- На карточке компании честно указывается источник: если БИН есть — обычная
  плашка «Реестр юридических лиц», если БИН нет — «Из бизнес-справочников» и
  отдельное пояснение, что организация не найдена в официальном реестре.

Запуск:

1. Остановить Node.js в Plesk.
2. Выполнить:

```bash
npm run import-directory-contacts -- --confirm-offline
```

Прогресс (номер обработанной строки) сохраняется в рабочей базе — при обрыве
достаточно запустить команду снова, обработка продолжится с места остановки.
После завершения запустить Node.js заново.

Для пробного прогона на части снимка, не трогая всю базу:

```bash
npm run import-directory-contacts -- --confirm-offline --limit-rows=5000
```
