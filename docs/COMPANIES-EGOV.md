# Единая база организаций Казахстана

Каталог использует один рабочий файл `data/companies.sqlite`. HTML-файлы для
каждой организации не создаются: каталог и карточки формируются динамически.

## Источники и приоритет

1. `egov_gbd_ul` — официальный открытый набор Министерства юстиции РК на
   `data.egov.kz`: БИН, названия, регистрация, юридический адрес, деятельность,
   руководитель и статус.
2. `business_directory_kz_2026` — предоставленная пользователем выгрузка
   бизнес-справочника: телефоны, email, сайты, мессенджеры, соцсети, график,
   способы оплаты, адреса, категории и координаты. Лицензия исходного
   поставщика в архиве не зафиксирована, поэтому происхождение явно указано, а
   записи без БИН не включаются в публичный sitemap.
3. `verified_override` — подтверждённое самой организацией исправление. Оно
   имеет наивысший приоритет и не перезаписывается последующими импортами.

Официальные поля не заменяются справочником. Отсутствующее значение не
выдумывается.

## Проверенный снимок справочника

В репозитории хранится только
`registry/companies-directory-contacts.ndjson.gz`:

- формат: потоковый NDJSON + gzip;
- 457 324 уникальные записи;
- 25 290 556 байт;
- SHA-256:
  `7d89fcc04c4ee1f10743c4dbf79400a0b94703f2cd945ddc9345667a7d0cc57c`;
- 0 повреждённых JSON, 0 строк без названия;
- удалено 157 735 точных дублей из исходных 615 059 строк;
- 456 848 адресов и 640 022 нормализованных телефонных/цифровых контакта
  без учёта социальных сетей;
- 7 076 категорий.

Полная статистика и контрольная сумма находятся в
`registry/companies-directory-contacts.manifest.json`.

`Казахстан.zip` и `Казахстан.rar` были альтернативными упаковками одной
выгрузки. Они не хранятся в Git и не должны загружаться в Plesk. Рейтинги и
счётчики отзывов без даты и проверяемого происхождения удалены. Полезные поля
— контакты, соцсети, график, способы оплаты, адреса и координаты — сохранены.

## Модель данных и экономия диска

Первая полностью нормализованная модель занимала 1 503 096 832 байта только
для справочника и была отклонена. Рабочая модель компактна:

- основное и первое контактное значение хранится в строке `companies`;
- дополнительные значения одного источника хранятся одним компактным JSON в
  `organization_details`;
- связь с исходной записью хранится 128-битным отпечатком в
  `organization_source_links`;
- подтверждённые исправления, неоднозначные совпадения и история запусков
  остаются отдельными небольшими таблицами;
- поиск FTS не дублирует исходный текст.

Полный контрольный импорт 457 324 строк занял около 453 MiB активных страниц
SQLite вместо 1,50 GB. Это измерение чистой тестовой базы, а не обещание
точного размера существующей production-базы.

## Правила сопоставления и дублей

Порядок сопоставления:

1. стабильная запись того же источника;
2. точное нормализованное название;
3. совместимые регион и адрес;
4. при нескольких правдоподобных компаниях — новая отдельная карточка и
   запись в `organization_merge_candidates`.

Одинаковое название не является достаточным доказательством дубля. Филиалы с
разными адресами сохраняются отдельно. Нечёткое совпадение никогда не
объединяется автоматически.

## Требования

- Node.js 22.5 или новее (`node:sqlite`);
- приложение Node.js/Passenger остановлено для любой записи в SQLite;
- резервная копия `data/companies.sqlite` скачана за пределы квоты Plesk;
- production-зависимости установлены командой:

```bash
npm ci --omit=dev --ignore-scripts
```

## Предварительная проверка

Без изменения базы:

```bash
npm run import-directory-contacts -- --dry-run
npm run organization-storage-plan
```

Вторая команда учитывает размер текущей базы, количество уже импортированных
справочных организаций, свободное место и безопасный бюджет базы 850 MiB.
Если расчёт не проходит, импорт блокируется до первой записи.

Лимит можно задать явно:

```bash
COMPANIES_MAX_DB_BYTES=891289600 npm run organization-storage-plan
```

`--ignore-space-check` предназначен только для восстановительных работ после
ручной проверки квоты. Обычный deployment не должен его использовать.

## Импорт

Если официальная база ещё не активирована:

```bash
npm run import-companies -- --all --confirm-offline
```

Затем:

```bash
npm run import-directory-contacts -- --confirm-offline
```

Импорт читает gzip построчно, сохраняет чекпоинт после каждой пачки и
идемпотентен по контрольной сумме. После обрыва нужно повторить ту же команду.
Она продолжит с `next_row`, а завершённый снимок повторно не импортирует.

Для контролируемой паузы:

```bash
npm run import-directory-contacts -- --confirm-offline --limit-rows=5000
```

После завершения запустить Node.js и проверить:

```bash
curl -I https://zakonexpertt.kz/companies
curl -I https://zakonexpertt.kz/en/companies
curl -I https://zakonexpertt.kz/company/ID-SLUG
```

## Откат

Команда импорта выводит короткий `runId`, например
`dir-20260731012651-7d89fcc0`. Пока записи не использованы более новым
импортом, запуск можно откатить:

```bash
npm run rollback-organization-import -- \
  --confirm-offline \
  --run-id=dir-20260731012651-7d89fcc0
```

Откат удаляет только данные конкретного запуска. Официальные компании и
подтверждённые исправления сохраняются. Перед откатом приложение также должно
быть остановлено.

## Поиск и международное SEO

Поиск работает по БИН, исходному названию, казахскому/русскому варианту,
детерминированной латинской транслитерации, телефону, email, сайту и
дополнительным контактам.

Индексируются пять полноценно локализованных входных страниц:

- `/companies` — русский;
- `/kk/companies` — қазақша;
- `/en/companies` — English;
- `/zh/companies` — 中文;
- `/tr/companies` — Türkçe.

Они имеют отдельные URL и взаимные `hreflang`. Карточки организаций не
переводятся машинно и не размножаются в sitemap: локализованные интерфейсы
карточек имеют canonical на исходную карточку и `noindex`. Это защищает сайт
от низкокачественных массовых переводов и сохраняет официальное название.

## Пересборка снимка

Новый исходный ZIP обрабатывается только локально:

```bash
npm run build-directory-snapshot -- --archive="/path/Казахстан.zip"
npm run compact-directory-snapshot
npm run analyze-directory-snapshot
```

Перед коммитом должны совпасть число строк, контрольная сумма в manifest и
результаты полного теста. Импортер намеренно не заменяет уже завершённый снимок
с другой контрольной суммой: обновление источника оформляется отдельной
проверенной миграцией с внешней резервной копией базы.
