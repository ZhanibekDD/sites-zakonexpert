# Контракт выгрузки data.egov.kz для ZakonExpert

Этот файл описывает единственный формат, который должен выдавать внешний сборщик. Он нужен, чтобы результат Claude импортировался в сайт одной командой без ручной правки.

## Готовое задание для Claude

Передайте Claude этот текст вместе со ссылкой на данный файл:

> Собери все опубликованные наборы категории `AVS-EI0B99eXTcgzfxyo` через официальные endpoints data.egov.kz. Для каждого набора определи текущую версию из паспорта, выгрузи все страницы API V4 с ключом только из локального `.env` и сформируй `recon-out/catalog.json` плюс `recon-out/records/*.json` строго по контракту ниже. Не помещай API-ключ в файлы, URL, stdout или Git. Проверь число наборов против `totalCount`, отсутствие дубликатов и наличие файла записей для каждого набора. После сбора выполни `npm run refresh-open-data -- --input-dir=./recon-out` и `npm run test:open-data`. Не изменяй шаблоны сайта и не коммить каталог `recon-out`.

## Что собирать

- Категория: `Государственный сектор`.
- ID категории: `AVS-EI0B99eXTcgzfxyo`.
- Каталог: `GET /datasets/getdatasetsre` с постраничным обходом до `totalCount`.
- Для каждого набора: паспорт, текущая версия, URL API и все страницы записей.
- Записи получать через официальный `/api/v4/{apiUri}/{version}` с `EGOV_API_KEY` из `.env`.
- Ключ нельзя записывать в JSON, логи, URL отчёта или коммит.

## Структура каталога результата

```text
recon-out/
  catalog.json
  records/
    {apiUri}-{version}.json
```

`catalog.json` — массив объектов:

```json
[
  {
    "index": "opendata-api-uri1787649025620",
    "version": "v8",
    "title": "Основные показатели деятельности ревизионных комиссий...",
    "description": "Показатели аудиторских мероприятий...",
    "agency": "Высшая аудиторская палата РК",
    "category": "Государственный сектор",
    "publishedAt": "2026-08-25T14:05:00+05:00",
    "updatedAt": "2026-08-25T16:27:00+05:00",
    "updateFrequency": "Ежеквартально",
    "datasetUrl": "https://data.egov.kz/datasets/view?index=opendata-api-uri1787649025620",
    "apiUrl": "https://data.egov.kz/api/v4/opendata-api-uri1787649025620/v8",
    "metaUrl": "https://data.egov.kz/meta/opendata-api-uri1787649025620/v8",
    "recordsFile": "records/opendata-api-uri1787649025620-v8.json",
    "complete": true
  }
]
```

Каждый файл в `records/` должен содержать JSON-массив всех записей набора. Пагинация считается законченной только после пустой страницы либо достижения официального `totalPages`. Лимит первой страницы не считается полным набором.

## Импорт в сайт

Из корня ZakonExpert:

```bash
npm run refresh-open-data -- --input-dir=/полный/путь/recon-out
npm run test:open-data
```

Импорт читает все записи, строит статистику и сохраняет публичный снимок в `data/open-data-snapshots.json`. Исходные `recon-out/records/*.json` в Git не добавляются.

## Проверки перед передачей

- число объектов в `catalog.json` совпадает с `totalCount` категории;
- импорт отклонит каталог, если в нём меньше 50 наборов, есть дубликат или отсутствует файл записей;
- для каждого объекта существует `recordsFile`;
- нет дубликатов `index + version`;
- `complete: true` ставится только после полного постраничного обхода;
- ни в одном файле нет API-ключа;
- ошибки отдельных наборов записываются в отдельный локальный лог, а не вместо массива записей.
