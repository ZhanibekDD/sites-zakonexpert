# Основа роста органического трафика ZakonExpert

## Что меняется

### 1. Индексируются не все компании подряд

Каждая карточка получает оценку полноты от 0 до 10. В расчёт входят валидный БИН, название, дата регистрации, адрес, вид деятельности, руководитель, статус, казахское название и регион.

- порог по умолчанию: 7;
- обязательны валидный 12-значный БИН и название;
- слабая карточка остаётся доступной посетителю по прямой ссылке и через поиск по БИН, но получает `noindex,follow`;
- sitemap компаний содержит только прошедшие порог карточки;
- оценка хранится в SQLite, поэтому фильтрация 800 000+ строк не создаёт полный скан на каждый запрос поискового робота.

Порог задаётся `COMPANY_INDEX_MIN_SCORE=7`. Его нельзя снижать только ради количества URL.

## Активация на Plesk

После слияния и обновления файлов:

1. Остановить Node.js в Plesk.
2. Выполнить:

   ```bash
   npm install --omit=dev --ignore-scripts --no-audit --no-fund
   npm run backfill-company-quality -- --confirm-offline
   ```

3. Запустить Node.js.
4. Проверить:

   ```bash
   npm run audit:live
   ```

Команда backfill выводит точное количество индексируемых и исключённых компаний. До её выполнения sitemap компаний намеренно не публикуются, чтобы не продолжать отправлять слабые карточки.

## 2. IndexNow больше не маскирует ошибки

Обычный запуск отправляет только основные страницы и новости:

```bash
npm run submit-indexnow
```

Один конкретный sitemap:

```bash
npm run submit-indexnow -- --sitemap=sitemap-laws.xml
```

Полная отправка всех sitemap оставлена только как явная аварийная/первичная операция:

```bash
npm run submit-indexnow -- --all
```

Скрипт отдельно показывает принятые и отклонённые URL и завершится ошибкой, если хотя бы один пакет не принят.

## 3. Первый кластер полезных инструментов

Раздел `/tools` объединяет:

- долг и пеню;
- предложение графика платежей;
- перевод МРП 2026 в тенге;
- предварительную госпошлину по имущественному иску;
- календарный/рабочий процессуальный срок.

У каждого инструмента отдельный canonical, описание, WebApplication/FAQ schema, источники и предупреждения. Завершённый расчёт фиксируется событием `calculator_completed`, поэтому можно оценить не только показы, но и реальное использование.
