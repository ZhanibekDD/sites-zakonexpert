# ZakonExpert Private CRM

Закрытая CRM работает внутри того же Node.js-приложения, но не индексируется и требует отдельный пароль.

## Что хранится

- клиент: ФИО, телефон, источник и тема обращения;
- статус: новый / связались / согласился / отказался / в работе / ждём оплату / оплачено / завершено / потерян;
- какая работа выполняется и внутренние заметки;
- обещание оплаты: сумма, дата, комментарий;
- фактически оплаченные суммы;
- договоры: название, номер, сумма, дата и ссылка на файл;
- история изменений;
- сообщения WhatsApp Cloud API после его подключения.

Основное хранилище: `data/crm.db`. CRM автоматически подхватывает существующие заявки из `data/leads.db`. При изменениях создаётся ежедневный JSON-бэкап в `data/crm-backups/`. Дополнительно в интерфейсе есть ручной экспорт CSV и JSON.

## Развёртывание в Plesk

1. Развернуть ветку с CRM.
2. В Node.js поменять startup file с `server.js` на `crm-entry.js`.
3. В переменных окружения Plesk добавить значения из секции CRM в `.env.example`:
   - `CRM_USERNAME`;
   - `CRM_PASSWORD`;
   - `CRM_SESSION_SECRET` (случайная строка 32+ символов);
   - `CRM_INTEGRATION_KEY` (другая случайная строка 32+ символов).
4. Не отправлять реальные секреты в чаты и не добавлять их в Git.
5. Перезапустить приложение.
6. Открыть `https://zakonexpert.kz/crm`.

CRM ставит `noindex`, `noarchive`, запрещает встраивание во frame, использует подписанную HttpOnly Secure SameSite=Strict сессию и CSRF-защиту на записи.

## Telegram

CRM использует уже подключённые `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`. Второй Telegram poller не запускается.

Новые заявки с сайта автоматически попадают в CRM. В Telegram дополнительно появляется CRM-карточка с кнопками статуса.

Команды:

```text
/crm
/client +77001234567 | Имя
/status +77001234567 | in_work
/promise +77001234567 | 50000 | 2026-09-05 | обещал после зарплаты
/paid +77001234567 | 50000
/contract +77001234567 | Договор на услуги | ZE-123 | 100000
/note +77001234567 | Перезвонить завтра
```

## Автоматическое добавление договоров

Для отдельного генератора договоров предусмотрен серверный endpoint:

```text
POST https://zakonexpert.kz/api/crm/integrations/contracts
X-CRM-Integration-Key: <CRM_INTEGRATION_KEY>
Content-Type: application/json
```

Пример тела:

```json
{
  "phone": "+77001234567",
  "name": "Клиент",
  "title": "Договор на услуги",
  "number": "ZE-123",
  "amount": 100000,
  "date": "2026-08-31",
  "fileUrl": "https://..."
}
```

Чтобы договоры из другого бота появлялись полностью автоматически, тот бот/сервис должен вызвать этот endpoint после успешного создания договора. Это надёжнее, чем пытаться читать сообщения другого Telegram-бота.

## WhatsApp Cloud API

Использовать только официальный WhatsApp Business Platform / Cloud API Meta. Не подключать браузерные эмуляторы, неофициальные библиотеки или обход блокировок.

После создания/подключения Meta Business App добавить в Plesk:

- `WHATSAPP_VERIFY_TOKEN`;
- `WHATSAPP_APP_SECRET`;
- `WHATSAPP_ACCESS_TOKEN`;
- `WHATSAPP_PHONE_NUMBER_ID`;
- `WHATSAPP_GRAPH_VERSION`.

Webhook callback URL:

```text
https://zakonexpert.kz/api/whatsapp/webhook
```

В Meta у webhook подписать WhatsApp `messages`. Входящие сообщения будут сохраняться в карточке клиента по номеру телефона. Ответ из CRM отправляется через официальный Cloud API и также сохраняется в истории CRM.

Cloud API не снимает существующие ограничения/блокировку WhatsApp. Сначала нужно восстановить доступ и состояние бизнес-аккаунта у Meta. Правила WhatsApp Business требуют согласия пользователя на дальнейшие сообщения; вне 24-часового окна после сообщения пользователя бизнес-инициированные сообщения отправляются через одобренные шаблоны.

## Восстановление после потери телефона/приложения

CRM хранит новые данные на сервере независимо от установленного WhatsApp-приложения. Поэтому удаление приложения в дальнейшем не уничтожит уже записанные в CRM обещания, статусы, договоры и сообщения, поступившие через Cloud API.

Старые переписки, которые существовали только локально в WhatsApp и не сохранились в резервной копии WhatsApp, CRM задним числом восстановить не сможет. Но существующие заявки сайта из `leads.db` автоматически импортируются, а сведения из Telegram-уведомлений можно восстановить отдельно при необходимости.
