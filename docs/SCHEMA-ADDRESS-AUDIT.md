# Аудит адреса в schema.org

## Обнаруженный конфликт

Два разных адреса для одного бренда (ZakonExpert) на разных страницах:

| Страница | Схема | Адрес |
|---|---|---|
| `public/index.html` (главная) | `LocalBusiness` | проспект Аль-Фараби, Алматы, 050059 |
| `public/contact.html` (контакты) | `LegalService` | ул. Конаева, 20, Талдыкорган, Алматинская область |

## Какой адрес реальный

**Талдыкорган (contact.html) — подтверждённый.** Признаки:
- `sameAs` в схеме contact.html указывает на конкретный, пронумерованный листинг 2ГИС: `https://2gis.kz/taldykorgan/firm/70000001111056987` — это не обобщённая ссылка, а точная привязка к реальной организации в 2ГИС.
- Ранее (в предыдущей сессии работы над этим сайтом) владелец предоставил реальные проверенные ссылки на 2ГИС/Яндекс.Карты/Instagram для NAP-консистентности (Этап 3), которые указывали на Талдыкорган.

**Алматы (index.html) — неподтверждённый, похож на плейсхолдер.** Признаки:
- `hasMap` указывал не на конкретную точку, а на обобщённый поисковый запрос `https://maps.google.com/?q=Алматы,+Казахстан` — так не выглядит реальная привязка к офису.
- Адрес без номера дома («проспект Аль-Фараби» без указания конкретного здания) — типичный признак сгенерированного/примерного адреса.
- Нет `sameAs` с конкретным листингом, подтверждающим этот адрес.

## Что сделано

Из `public/index.html` (схема `LocalBusiness`) удалены:
- `address` (PostalAddress: проспект Аль-Фараби, Алматы, 050059);
- `geo` (GeoCoordinates: 43.2220, 76.8512);
- `hasMap` (обобщённая ссылка на карту).

Оставлено без изменений:
- `areaServed: { "@type": "Country", "name": "Казахстан" }` — уже присутствовало, корректно описывает дистанционную работу по всей стране;
- `telephone`, `email`, `priceRange`, `openingHoursSpecification`, `description`, `serviceType`, `image`, `url`, `name` — всё это подтверждённые, не адресные данные.

`public/contact.html` **не изменялся** — адрес там подтверждён конкретным 2ГИС-листингом.

## Что должен подтвердить владелец вручную

1. **Является ли ул. Конаева, 20, Талдыкорган действующим адресом для приёма клиентов** (юридический адрес ИП может отличаться от клиентского офиса — правило "не путать" явно оговорено в задаче). Если да — оставить как есть.
2. Если фактического офиса для очного приёма клиентов нет вообще (сайт заявляет дистанционную работу по Казахстану) — рассмотреть, не стоит ли также убрать адрес из `contact.html`, оставив там только `areaServed` и контакты, как сейчас сделано на главной. Это решение зависит от бизнес-модели и не принято автоматически — требует подтверждения владельца.
3. Если в будущем появится подтверждённый офис в Алматы (или где-либо ещё) для очного приёма — добавить `PostalAddress` заново, но только с реальным адресом и подтверждающим `sameAs`/2ГИС-листингом, а не заново сгенерированным плейсхолдером.
