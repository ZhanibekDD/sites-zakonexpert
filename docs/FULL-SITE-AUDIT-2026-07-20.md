## Итог

Сайт уже содержит примерно **821 тысячу индексируемых страниц**: 805 281 компанию, 6 320 карточек нотариусов, 2 079 ЧСИ, 4 257 адвокатов, страницы законов, организаций и новостей. Главный предел роста сейчас — не количество URL, а стабильность обхода, безопасность административных функций и качество/уникальность массовых страниц.

Проверены живая версия, основные страницы, sitemap, новости, изображения, формы без отправки реальных заявок, код, тесты, зависимости, хранилище и реестры.

## P0 — критично

### 1. Административные API были открыты

`/api/news/status` отвечал без ключа, а GET-маршруты импорта, очистки и обновления реестров становились открытыми, если `ADMIN_KEY` отсутствовал. Посторонний запрос мог очистить или перезаписать данные.

Исправлено в ветке аудита:

- admin API закрывается с 503, если `ADMIN_KEY` не настроен или короче 24 символов;
- ключ принимается только в `x-admin-key`, а не в URL;
- сравнение ключа выполняется с постоянным временем;
- все изменяющие операции переведены с GET на POST;
- `/api/telegram/setup` также защищён;
- модерация комментариев переведена с пароля в URL на HTTP Basic Auth.

После деплоя в Plesk нужно задать случайный `ADMIN_KEY` длиной 32+ символа.

### 2. Компаниями можно было исчерпать память Node.js

В sitemap index находится 81 файл компаний по 10 000 URL. Каждый файл занимает около 2.4 МБ. Приложение кэшировало **все** запрошенные файлы и после запуска заранее прогревало их — потенциально около 190 МБ постоянной памяти. На живом сайте зафиксированы 502 у `/sitemap-laws.xml`, `/sitemap-companies-6.xml` и одна из основных страниц во время нагрузки.

Исправлено:

- размер чанка уменьшен до 5 000 URL;
- кэш ограничен двумя последними sitemap;
- прогрев всех sitemap при старте удалён;
- добавлены браузерные/прокси Cache-Control заголовки.

### 3. Не было Content-Security-Policy

Helmet работал с отключённым CSP. Добавлена политика для собственного кода, Bootstrap CDN, шрифтов, Яндекс Метрики, карт и HTTPS-изображений. Также скрыт `X-Powered-By`, ограничены таймауты и добавлены лимиты на дорогие внешние API и формы.

## P1 — влияет на трафик и клиентов

### Большие каталоги

На живом сервере до деплоя исправлений размеры HTML составляли:

- `/courts` — около 570 КБ, 1 329 ссылок;
- `/lombards` — около 324 КБ;
- `/collectors` — около 260 КБ;
- `/mfo` — около 251 КБ.

Исправлено серверной пагинацией по 60 карточек и серверным поиском. Локальные размеры после изменения:

- `/courts` — 91 КБ (−84%);
- `/lombards` — 61 КБ (−81%);
- `/collectors` — 87 КБ (−67%);
- `/mfo` — 69 КБ (−72%);
- региональная страница `/lawyers` — 33 КБ.

Для страниц 2+ созданы собственные canonical, поисковая выдача каталогов закрыта `noindex,follow`.

### Новости

Парсер работает: 936 материалов, 758 опубликовано, последний запуск 19.07.2026, ошибок импорта не было. Полные разделы и изображения отображаются. Добавлен локальный SVG fallback, если издатель закроет изображение.

Остаётся редакционный риск: нельзя превращать чужие RSS в копии статей. Нужно публиковать факты, краткое резюме, собственный юридический разбор и ссылку на источник. Google News RSS и изображения издателей требуют отдельной проверки условий коммерческого использования.

### Реестры

- нотариусы: официальный снимок ENIS обновлён во время аудита — 6 320 записей, 20 палат, 5 778 телефонов и 5 802 email; выборка живых карточек содержит лицензию;
- ЧСИ: 2 079 записей; лицензии присутствуют, телефоны отсутствуют только у 2 записей в локальной проверке;
- адвокаты: подключён официальный публичный API «Е‑Заң көмегі» — 4 257 уникальных анкет из 4 260 ответов API, 4 254 валидных телефона, 4 233 email, 20 регионов плюс 38 анкет без определённого региона; две явные тестовые анкеты исключены, один повтор ID объединён;
- компании: 805 281 записей уже опубликовано.

Для каждой карточки нужно показывать источник и дату проверки. Неизвестное поле лучше обозначать «не опубликовано в официальном источнике», а не угадывать.

Обновление адвокатов запускается раз в неделю вместе с импортом реестров или вручную защищённым `POST /api/lawyers/refresh`. Снимок заменяется только после проверки минимального количества записей, регионов и коллегий.

### Мягкие 404

Карточки по несуществующим slug отвечали редиректом 302 на каталог. Исправлено для нотариусов, ЧСИ, адвокатов, компаний, банков, судов, МФО, ломбардов, коллекторов, законов и новостей: теперь возвращается настоящий HTTP 404 без `Location`, с `noindex,follow` и полезными ссылками.

### Массовое SEO

805 тысяч карточек — уже почти миллион страниц. Простое увеличение количества не даст миллион посещений. Массовые страницы должны отвечать на отдельный запрос и содержать проверяемые уникальные данные; иначе возникает риск scaled content abuse. Приоритет: стабильные sitemap, региональные/отраслевые хабы, устранение дублей, полезные фильтры и обновление данных.

Официальные рекомендации Google:

- https://developers.google.com/search/docs/crawling-indexing/large-site-managing-crawl-budget
- https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap

## Порядок после слияния

1. Задать `ADMIN_KEY` в Plesk и перезапустить Node.js.
2. Запустить `npm install --omit=dev --ignore-scripts --no-audit --no-fund`.
3. Выполнить `npm run audit:live`.
4. Повторно отправить `/sitemap-index.xml` в Google Search Console и Яндекс Вебмастер.
5. Выполнить защищённый `POST /api/lawyers/refresh` и проверить `/lawyers`, `/sitemap-lawyers.xml`.
6. Включить мониторинг 502 и времени ответа sitemap; живая версия до деплоя всё ещё показывает старые 502 и тяжёлые каталоги.
